## 1. Что выяснилось по документации

### 1.1 hh.ru — реализуемо полностью
- Официальная документация: https://github.com/hhru/api (раздел `employer_negotiations.md`).
- Есть методы работодателя: список откликов по вакансии, просмотр отклика с резюме, смена статуса, переписка.
- Есть **Webhook API** (подписка на уведомления, только для работодателя) — можно получать событие о новом отклике мгновенно.
- ⚠️ **Методы откликов помечены как требующие «платного доступа для работодателя»** (в доке значок `emp_paid`, ошибка `403 action_must_be_payed` без доступа). В блоге hh.ru 2022 г. писали, что получать отклики во внешние системы можно без покупки услуг — информация противоречивая, **надо уточнить у вашего менеджера hh.ru**, что входит в ваш тариф.
- Нужно: зарегистрировать приложение на https://dev.hh.ru (проходит модерацию), авторизоваться аккаунтом менеджера работодателя (OAuth).
- Бонус: в API есть и **поиск по базе резюме** — если когда-нибудь купите доступ к базе, «холодный» поиск на hh подключается почти бесплатно по коду.

### 1.2 Indeed — только обходными путями
- **Job Sync API** (GraphQL) — только для ATS-партнёров, прямым работодателям недоступен, онбординг через Partner Console, ревью интеграции, ~6 недель.
- **Indeed Apply с postUrl** (отклик прилетает JSON-ом на наш сервер) работает только при публикации вакансий через **XML-фид** с собственного карьерного сайта. Если вакансии размещаются руками в кабинете Indeed — этот путь закрыт.
- Реальные варианты:
  1. **Почта (рекомендую для старта).** Indeed присылает письмо о каждом новом отклике. Заводим отдельный ящик (напр. `hiring@...`), сервис читает его через Gmail API, достаёт резюме (вложение или текст), оценивает. ⚠️ Надо проверить на вашем аккаунте, приходит ли резюме вложением (зависит от настроек кабинета/страны).
  2. **Ручная выгрузка.** HR раз в день скачивает резюме из кабинета пачкой и кидает в папку Google Drive / в бота.
  3. **ATS-партнёр Indeed** (Workable, Zoho Recruit, Manatal и т.п.): вакансии публикуются из ATS, отклики падают в ATS, а у ATS есть нормальный API. Чище всего, но +подписка на ATS.
- ✏️ Поправка к исходному ТЗ: у Indeed **есть** «холодный» поиск — **Indeed Smart Sourcing** (база резюме, платно, от ~$120/мес в США). Но API нет — только руками в кабинете.

### 1.3 LinkedIn — главный риск проекта
- **Поиска людей через официальный API нет.** Профильные данные отдаются только партнёрам (Recruiter System Connect — для ATS-вендоров).
- **Парсинг LinkedIn запрещён пользовательским соглашением.** Пример: LinkedIn подал в суд на Proxycurl (крупнейший сервис парсинга) в январе 2025, в июле 2025 тот закрылся. Автоматизация через ваш личный/рекрутерский аккаунт (Phantombuster, Unipile, Apify и т.п.) = высокий риск бана аккаунта HR.
- Что можно делать:
  - **A. Провайдер данных (рекомендую для автопоиска).** People Data Labs / Coresignal — продают лицензированные базы профилей (в т.ч. со ссылкой на LinkedIn) с API поиска по должности, навыкам, стране, опыту. Мы отправляем фильтры → получаем кандидатов с опытом/навыками/ссылкой на LinkedIn → ИИ оценивает → в таблицу. HR сам пишет человеку в LinkedIn. Платно, за запись. Перед покупкой запросить у вендора письменно, откуда данные.
  - **B. Официальный LinkedIn Recruiter / Recruiter Lite** (+ ИИ-агент Hiring Assistant, вышел в 2025). Ищет хорошо, но всё внутри LinkedIn, без выгрузки в нашу систему. Наша система может помогать: генерировать boolean-строку поиска из требований и оценивать профили, которые HR перекинул (ссылка/PDF «Save to PDF»).
  - **C. X-ray поиск** через поисковый API (Brave Search API / SerpApi: `site:linkedin.com/in "interior designer" Dubai`) — даёт только заголовок и сниппет, точность низкая. Как дешёвый источник ссылок для дальнейшего обогащения через A. (Google Custom Search API закрыт для новых клиентов и отключается 01.01.2027.)
- Итог: **«просто парсим LinkedIn» делать не будем** — предлагаю A (+ ручной канал B).

## 2. Как это будет работать для HR (пользовательский сценарий)

```
1. HR создаёт вакансию в таблице (или голосом в боте — ИИ сам разложит на требования)
2. Нажимает «Запустить» (галочка в таблице / кнопка в боте)
3. ИИ превращает требования в чек-лист с весами → HR видит его и при необходимости правит
4. Дальше автоматически:
   • LinkedIn (провайдер данных): поиск по фильтрам → оценка → лист кандидатов
   • hh.ru: каждые 15 мин забираем новые отклики → оценка → лист кандидатов
   • Indeed: каждые 15 мин читаем ящик откликов → оценка → лист кандидатов
5. HR получает в Telegram:
   • сразу — если пришёл кандидат категории A (балл ≥ 80)
   • 2 раза в день (10:00 и 16:00) — сводку: «по вакансии X: +12 откликов, 3 A, 5 B, 4 C»
6. HR открывает таблицу, видит отсортированный список с объяснением, ставит статус
   (Связаться / Отказ / Интервью), пишет человеку руками
```

### Триггер для откликов (ваш вопрос: «2 раза в день / каждый / каждые 10?»)
Предлагаю **разделить обработку и уведомления**:
- **Обработка — постоянно** (опрос каждые 15 мин или вебхук hh). Оценка одного резюме стоит центы, копить смысла нет, а сильный кандидат не должен ждать полдня.
- **Уведомления — пачкой 2 раза в день**, кроме «горячих» (A) — о них сразу.
- Интервалы и время настраиваются в листе «Настройки».

## 4. Как ИИ оценивает (логика скоринга)

Делим работу на два шага, чтобы оценки были **объяснимыми и стабильными**:

1. **Требования → чек-лист (один раз на вакансию).** Claude превращает текст HR в список критериев:
   `{критерий, тип: must/важно/желательно/стоп, вес, как проверять}`. HR может поправить.
2. **Резюме → оценка по каждому пункту.** Claude получает резюме + чек-лист и по каждому критерию возвращает: `да / частично / нет / нет данных` + **цитату из резюме**, на основании которой решил.
3. **Итоговый балл считает код, а не ИИ** (взвешенная сумма). Не выполнено must-have или сработал стоп-фактор → автоматически категория C с пометкой.
4. Категории: **A** ≥ 80, **B** 60–79, **C** < 60 (настраивается).
5. Дополнительно ИИ пишет: выжимку в 2–3 строки, красные флаги, 2–3 вопроса для интервью.

Модель: дешёвая (Haiku) для массовой оценки, более сильная (Sonnet) — опционально для финального ранжирования топ-кандидатов. Ориентир по стоимости — единицы центов за резюме.

## 6. Архитектура и связь с CorporateBot

```
                 ┌───────────────────── Google Sheets «HR Скрининг» ─────────────────────┐
                 │  Вакансии (вход)   Настройки   V-xxx Кандидаты (выход)   Журнал        │
                 └───────▲────────────────────────────▲──────────────────────────────────┘
                         │ читает/пишет               │ пишет
┌──────────────┐   ┌─────┴────────────────────────────┴──────┐   ┌─────────────────────┐
│ CorporateBot │──▶│        hr-screening (отдельный сервис)  │──▶│ Telegram-уведомления │
│ раздел «HR»  │   │  scheduler → sources → scoring → sheets │   └─────────────────────┘
│ (опционально)│   │  sources: hh_api | indeed_mail |        │
└──────────────┘   │           linkedin_provider | manual    │
                   └─────────────────────────────────────────┘
```

- **Отдельный репозиторий/ветка, отдельный процесс (systemd-служба `hr-screening`)** на том же Hetzner-сервере. Стек тот же, что у бота (Python 3.12, anthropic, gspread) — проще поддерживать.
- CorporateBot **не импортирует код** HR-сервиса. Связь — только через Google-таблицу (бот пишет «новая вакансия / запустить / вот резюме», сервис подхватывает). Если что-то сломается в HR — бот продолжит работать, и наоборот.
- Что удобно встроить в бота (переиспользуем уже готовое голос → Whisper → Claude → таблица):
  - **🧑‍💼 Новая вакансия** — HR надиктовывает требования голосом, ИИ раскладывает по полям, HR подтверждает.
  - **▶️ Запустить поиск** по вакансии.
  - **📎 Оценить резюме** — кинуть PDF или ссылку LinkedIn → оценка в чат и в таблицу (ручной канал для LinkedIn/Indeed).
  - **📊 Сводка** по вакансии.
  - Уведомления о кандидатах A.
- Альтернатива: **отдельный HR-бот** (свой токен). Полная изоляция, но ещё один бот у HR. Решаем вместе.

## 9. Риски и ограничения (честно)

1. **LinkedIn**: полностью автоматический «парсинг LinkedIn» = нарушение правил и риск бана/иска. Предлагаемая схема с провайдером данных — платная и не покрывает 100% профилей.
2. **hh.ru**: работа с откликами через API может требовать платного доступа — уточнить до старта этапа 2.
3. **Indeed**: нет API для прямого работодателя; почтовый канал зависит от формата писем Indeed.
4. **Персональные данные.** Резюме — персональные данные. Для граждан РФ (hh.ru) действует 152-ФЗ, включая требование первичного хранения данных в РФ — Google Sheets и сервер Hetzner (Германия/Финляндия) под это не подходят. Для ОАЭ — PDPL, для США — законы штатов. Передача резюме в Claude API — тоже обработка третьей стороной. **Рекомендую показать схему юристу**; технически можно хранить в таблице только минимум (имя, ссылка, балл, выжимка), без контактов.
5. ИИ-оценка — помощник, не решение: финальный отбор за HR, все оценки с цитатами-обоснованиями, чтобы было видно, почему такой балл.
